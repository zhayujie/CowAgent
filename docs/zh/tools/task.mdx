后台任务让 Agent 不必占着对话一步步完成工作：交代清楚目标后，它在后台独立执行，你可以继续聊别的、关掉页面，做完或需要你拍板时再通知你。配合审批规则，发送邮件、推送代码、删除文件等敏感操作会先停下来等你确认，**在执行时强制拦截，不依赖提示词**。

<Note>
该功能目前为 Beta，默认关闭。关闭时不显示看板和提醒，不检查审批规则，定时任务也保持原有执行方式，对现有使用没有任何影响。
</Note>

## 开启

在控制台 **配置 → Agent 配置** 中打开「后台任务与审批」，或在 `config.json` 中添加：

```json
{
  "task": {
    "enabled": true,
    "chat_create": false,
    "max_concurrency": 2,
    "notify_webhook": "",
    "approval_rules": []
  }
}
```

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `enabled` | `false` | 总开关 |
| `chat_create` | `false` | 是否允许在对话中让 Agent 创建后台任务（`task_create` 工具）。关闭时对话完全保持原样 |
| `max_concurrency` | `2` | 同时执行的后台任务数（1–10），超出的排队等待。定时任务不占名额 |
| `notify_webhook` | 空 | 可选。有待审批、待验收或任务失败时，向该地址 POST 一条 JSON 通知 |
| `approval_rules` | `[]` | 审批规则，见下文。为空时所有操作照常直接执行 |

## 创建任务

有三种方式：

- **看板手动创建**：在「任务 → 看板」点击 **新建任务**，写清要做什么。可选择执行的 Agent，以及是否需要完成后验收。
- **定时任务**：开启后，「Agent 动态任务」类型的定时任务到点时会作为后台任务执行，同样受审批规则约束，并出现在看板上。到点立即执行，不占并发名额；结果仍按原方式发送到定时任务配置的接收者，图片和文件照常发送。同一个定时任务上一次还没结束时，本次触发会跳过。
- **对话中委托**：需要在配置中打开 `chat_create`。在对话里明确说「放到后台做」「做完通知我」等，Agent 会调用 `task_create` 创建任务并立即回复，不会占用当前对话。只有你明确要求时才会这样做，普通请求仍在对话中直接完成。

## 看板

「任务」页新增 **看板** 标签，按状态分为五列：

| 列 | 说明 |
| --- | --- |
| 排队中 | 等待空闲的执行名额 |
| 执行中 | 正在执行，显示已用时长 |
| 等我处理 | 等待你审批某个操作，或等待你验收结果 |
| 已完成 | 结果可在详情中查看、复制 |
| 失败 / 已停止 | 显示失败原因，可一键重新执行 |

点击卡片打开详情。执行过程和对话页面的展示方式一致：思考、每一步工具调用和输出都可以展开查看，执行中实时刷新。右侧是任务信息、待处理的审批和审批记录，也可以停止、重新执行或删除任务。

详情底部的输入框可以随时给任务补充要求：

- **执行中**：要求会在当前步骤结束后生效，不用停下任务。
- **排队中 / 等待审批**：要求会在开始执行或审批处理后一并带上。
- **等待验收**：写下的内容就是返工意见。
- **已完成 / 失败 / 已停止**：任务会带着完整上下文接着执行。由定时任务转来的任务，补充执行的结果只在看板中查看，不会再发给定时任务的接收者。

「重新执行」则会清空执行过程，从最初的任务内容重新开始。

## 审批规则

在看板右上角 **审批规则** 中管理。每条规则包括：

| 字段 | 说明 |
| --- | --- |
| 工具名 | 要拦截的工具，支持 `*` 通配和逗号分隔，如 `bash`、`*mail*,send` |
| 匹配内容 | 可选。对调用参数（JSON）做不区分大小写的正则匹配，如 `git\s+push`；留空表示该工具的所有调用 |
| 动作 | **需审批**：先停下来等你确认；**禁止**：直接拒绝，告诉 Agent 换个做法 |

面板中提供了推送代码、递归删除、发布部署、发送邮件等常用模板，可一键添加后再调整。

审批规则对后台任务和普通对话**都生效**。命中「需审批」的调用不会执行，Agent 会先完成不依赖它的部分，然后停下来说明在等哪一项审批。

## 处理审批

有待处理事项时，控制台右上角的铃铛会显示数量，点开即可处理；看板的「等我处理」列和对话中被拦截的工具调用下方也会出现审批卡片。

- **通过**：直接执行当时被拦下的那次调用，并把结果交还给 Agent 继续。
- **驳回**：可填写原因，Agent 会收到你的意见并调整做法，不会再执行原操作。
- **更多**：先修改调用参数再通过；也可以勾选「以后这类操作自动通过」，这会停用匹配到的规则。
- **验收**：对需要验收的任务，选择 **通过验收** 完成任务，或 **返工** 并写下修改意见，任务会按意见重新给出结果。

在微信、飞书、钉钉等通道中，Agent 会提示审批编号，直接回复即可：

```
通过 3
驳回 3 先别推送，等我检查完
```

只有一项待处理时可以省略编号。只有发起该操作的会话能处理对应审批。

## 结果与通知

- 看板手动创建的任务，结果在看板中查看；浏览器会弹出通知（需在控制台开启任务通知）。想追问或修改，直接在任务详情里继续补充。
- 对话中创建的任务完成后，结果会发回原会话，并写入该会话的上下文，可以直接追问。
- 配置了 `notify_webhook` 时，待审批（`approval_pending`）、待验收（`accept_pending`）、任务完成（`task_done`）和失败（`task_failed`）都会推送一条 JSON。由定时任务转来的后台任务只推送需要你处理的事件和失败。

```json
{
  "event": "approval_pending",
  "task_id": 12,
  "approval_id": 3,
  "title": "整理本周 issue 周报",
  "text": "【待审批 #3】任务 #12「整理本周 issue 周报」要执行：推送代码\n动作：bash  git push origin main\n回复「通过 3」或「驳回 3 原因」"
}
```

<Tip>
后台任务运行在独立会话中，不会出现在对话列表里，也不会触发自主进化。停止服务时正在执行的任务，会在下次启动后重新排队执行。
</Tip>
