> Integrate CowAgent into Feishu via a custom enterprise app. Supports p2p chat and group chat (@bot), uses WebSocket long connection (no public IP needed), supports streaming typewriter replies and voice messages.

<Note>
  You need to be a Feishu enterprise user with admin privileges.
</Note>

## 1. Setup

### Option 1: One-click Scan to Create (Recommended)

Open **Channels → Add Channel → Feishu** in the web console and scan to create an app. If Feishu returns the scanning user's Open ID, CowAgent automatically adds it to that instance's Owner list.

<img src="https://cdn.link-ai.tech/doc/20260505181126.png" width="800"/>

<Note>
  1. Requires `lark-oapi` ≥ 1.7.1.
  2. The created app comes with all required permissions (messaging, card read/write, group events, etc.) and event subscriptions pre-configured — no manual setup on the developer console needed. Currently only the Feishu mainland version is supported (Lark international not yet supported).
</Note>

When starting from CLI without `feishu_app_id` configured, the QR code is also printed to the terminal.

### Option 2: Manual Setup

Manually create a custom app on the Feishu Developer Platform, then connect via Web Console or config file.

**Step 1: Create the App**

1. Go to [Feishu Developer Platform](https://open.feishu.cn/app/), click **Create Enterprise Custom App**:

<img src="https://img-1317903499.cos.ap-guangzhou.myqcloud.com/docs/feishu-hosting-create-app.jpg" width="500"/>

2. In **Add App Capabilities**, add the **Bot** capability:

<img src="https://img-1317903499.cos.ap-guangzhou.myqcloud.com/docs/feishu-hosting-add-bot.jpg" width="800"/>

3. In **Permission Management**, paste the following permissions and **Batch Enable** all:

```
im:message,im:message.group_at_msg,im:message.group_at_msg:readonly,im:message.p2p_msg,im:message.p2p_msg:readonly,im:message:send_as_bot,im:resource,cardkit:card:write
```

<img src="https://cdn.link-ai.tech/doc/feishu-hosting-add-auth2.png" width="800"/>

4. Get `App ID` and `App Secret` from **Credentials & Basic Info**:

<img src="https://img-1317903499.cos.ap-guangzhou.myqcloud.com/docs/feishu-hosting-appid-secret.jpg" width="800"/>

**Step 2: Connect to CowAgent**

<Tabs>
  <Tab title="Web Console">
    Open the web console, go to **Channels**, click **Add Channel**, choose **Feishu**, switch to the **Manual** tab, enter App ID and App Secret, then click connect.
  </Tab>
  <Tab title="Config File">
    Add the following to `config.json` and start the program:

    ```json
    {
      "channel_type": "feishu",
      "feishu_app_id": "YOUR_APP_ID",
      "feishu_app_secret": "YOUR_APP_SECRET",
      "feishu_stream_reply": true
    }
    ```

    | Parameter | Description | Default |
    | --- | --- | --- |
    | `feishu_app_id` | Feishu app App ID | - |
    | `feishu_app_secret` | Feishu app App Secret | - |
    | `feishu_owner_open_ids` | Optional list of owner Open IDs for this bot | `[]` |
    | `feishu_private_memory_mode` | Direct chat memory mode for the instance | `owner_workspace` |
    | `feishu_stream_reply` | Enable streaming typewriter reply | `true` |
    | `feishu_detailed_card` | Use a detailed card (tool calls, thinking process, elapsed time) for streaming replies; off keeps the plain typewriter card | `true` |
  </Tab>
</Tabs>

**Step 3: Publish the App**

1. After Cow is running, go to **Events & Callbacks** in the Feishu Developer Platform, choose **Long Connection** mode and save:

<img src="https://cdn.link-ai.tech/doc/202601311731183.png" width="600"/>

2. Click **Add Event**, search for "Receive Message" and choose **Receive Message v2.0**.

3. (Optional) Under **Callbacks**, add **Card Action Trigger** (`card.action.trigger`) to enable `/tasks` scheduler commands; add the **Message Recalled** (`im.message.recalled_v1`) event to cancel a task by recalling its message.

4. Click **Version Management & Release**, create a version and apply for **Production Release**. Approve the request in the Feishu client:

<img src="https://cdn.link-ai.tech/doc/202601311807356.png" width="600"/>

## 2. Features

| Feature | Status |
| --- | --- |
| P2P chat | ✅ |
| Group chat (@bot) | ✅ |
| Text messages | ✅ send/receive |
| Image messages | ✅ send/receive |
| Voice messages | ✅ send/receive |
| Quoted replies | ✅ quoted text and rich-post context |
| Streaming reply | ✅ (powered by Feishu cardkit streaming card) |
| Markdown card | ✅ remote images are uploaded to Feishu for static and final streaming cards |
| Detailed card | ✅ tool calls, thinking process and elapsed time (controlled by `feishu_detailed_card`, on by default) |
| Scheduler controls | ✅ `/tasks` list with enable, disable and delete buttons |

<Note>
  Streaming reply requires the `cardkit:card:write` permission (already enabled by one-click creation) and Feishu client version ≥ 7.20. Older clients see an upgrade prompt; if the permission or version is not satisfied, replies fall back to plain text automatically.
</Note>

## 3. Usage

After connection, search for the bot name in Feishu to start a chat.

To use in groups, add the bot to a group and @-mention it.

Send `/tasks` in a private chat, or @-mention the bot with `/tasks` in a group, to manage tasks belonging to that chat.

**Receive direct messages** is enabled by default. You can turn it off for each bot in the Feishu channel settings in the web console or desktop app. Group messages still work.

### Member profiles and memory

Set the owner list on each bot using Open IDs (`ou_...`) for its app. In manual setup, **Look up Feishu application owner** requires `application:application:self_manage` or `admin:app.info:readonly`. When the lookup succeeds, select **Add as Owner** and save the settings. If Feishu returns the scanning user's Open ID during registration, CowAgent adds that ID to the target instance automatically.

Both settings live in the instance's `credentials` in `<agent_workspace>/agents/team.json`. Startup migration matches the old App ID to a single instance and respects existing lists, including empty lists. After saving the instance, CowAgent removes the old flat fields. Ambiguous bindings stay on disk for review.

If an existing single-Agent installation does not yet have `team.json`, migration creates it and adds the Feishu settings. Other legacy channels such as DingTalk continue reading their settings from `config.json`.

- `owner_workspace` (default) gives configured Owners the workspace `USER.md`, `MEMORY.md`, and daily memory. Other senders use separate memory. An empty list gives everyone separate memory.
- `per_user` gives every direct chat sender a separate profile and memory, including configured Owners.
- `shared` gives all direct chat senders with a valid identity the same workspace profile and memory. A verified legacy bot can retain shared behavior by selecting this mode.

Conversation history stays separate by sender. Earlier transcripts remain under their original sessions. New incoming messages use sessions keyed by app, instance, and memory access, so switching to personal memory won't load the workspace transcript.

To verify an existing Owner binding, temporarily set `"debug": true` in `config.json` and restart CowAgent. Send a recognizable private message to the bot, then compare `event.sender.sender_id.open_id` in the matching receive event in `run.log` with the instance's Owner list. Restore the previous log level afterward.

- **Group chats** share memory per group within the same Feishu app and Agent workspace, even with shared sessions disabled. Each sender has a separate Markdown profile in that group. Group chats skip the workspace's root `USER.md`, `MEMORY.md`, and `BOOTSTRAP.md`.
- **Direct chats** outside the workspace scope use a private profile and memory for that sender. Memory search, reads, and automatic summaries follow the same scope.
- **Profile updates** use the workspace's root `USER.md` in direct chats with workspace access. Group chats and scoped direct chats use `member_profile`. Earlier profiles and unlabeled messages remain available in their original locations.

<Note>
  File and memory tools apply the selected scope. Personal chats and group chats use a restricted set of tools.
</Note>
