Web コンソールは CowAgent のデフォルトチャネルです。起動後に自動的に実行され、ブラウザを通じて Agent と対話できるほか、モデル、Skill、メモリ、チャネルなどの設定をオンラインで管理できます。

## 設定

```json
{
  "channel_type": "web",
  "web_host": "0.0.0.0",
  "web_port": 9899,
  "web_password": "",
  "enable_thinking": false
}
```

| パラメータ | 説明 | デフォルト値 |
| --- | --- | --- |
| `channel_type` | `web` に設定 | `web` |
| `web_host` | Web サービスのリスンアドレス。空欄の場合、パスワード未設定なら `127.0.0.1`（ローカルのみ）、パスワード設定後は `0.0.0.0` でリスンします。コンソールから変更することもできます（下記「アクセス URL」を参照） | `""` |
| `web_port` | Web サービスのリスンポート | `9899` |
| `web_public_url` | 表示アドレス。API の URL、共有リンク、埋め込みコードに使われます。ドメインでアクセスする場合はドメインを入力、空欄なら自動検出 | `""` |
| `web_password` | アクセスパスワード。空欄の場合はパスワード保護が無効。`0.0.0.0` でリスンする場合は設定を推奨 | `""` |
| `web_session_expire_days` | ログインセッションの有効日数 | `30` |
| `web_file_serve_root` | web コンソールが直接読み取り/送信できるファイルの追加ルートディレクトリ（デフォルトはユーザーのホームディレクトリ）。設定済みの Agent ワークスペース（無効化された Agent を含む）と開いているプロジェクトディレクトリも常に許可されます。`/` に設定するとファイルシステム全体を許可 | `"~"` |
| `enable_thinking` | 深い思考モードを有効化するか | `false` |

パスワード設定後、コンソールへアクセスする際にはまずパスワード入力によるログインが必要です。ログイン状態はデフォルトで 30 日間保持され、その間はサービスを再起動しても再ログインは不要です。パスワードはコンソールの「設定」ページからオンラインで変更することもできます。同じ接続元からパスワードを 5 回続けて間違えると、10 分間ロックされます。

## アクセス URL

プロジェクト起動後、以下にアクセスしてください：

- ローカル実行: `http://localhost:9899`
- サーバー実行: `http://<server-ip>:9899`

<Note>
  サーバーのファイアウォールとセキュリティグループで該当ポートが許可されていることを確認してください。
</Note>

コンソールの「設定 → 連携設定 → アクセスアドレス」で次の項目を変更できます：

- **表示アドレス**：API の URL、共有リンク、埋め込みコードに使われるアドレス。ドメインでアクセスする場合はドメインを入力し、空欄なら自動検出します。
- **リスンアドレス**：サービスがリスンする IP とポート。`127.0.0.1` はこのマシンからのみアクセス可能、`0.0.0.0` はローカルネットワークやインターネット上の他のデバイスからもアクセスでき、事前にアクセスパスワードの設定が必要です。保存するとサービスは再起動せずに新しいアドレスへ切り替わり、新しいアドレスが使えない場合は元のアドレスに戻ります。他のデバイスからアクセスできる状態では、このマシンのローカルネットワークアドレスが下に表示されます。

## HTTPS とドメインでのアクセス

ドメインと HTTPS でコンソールを公開するには、次のいずれかの方法を使います。

**方法 1：nginx リバースプロキシ（推奨）**。TLS は nginx で終端し、HTTP でコンソールに転送します。あわせて `"web_host": "127.0.0.1"` を設定し、コンソールに nginx 経由でのみアクセスできるようにします：

```nginx
server {
    listen 443 ssl;
    server_name cow.example.com;

    ssl_certificate     /etc/letsencrypt/live/cow.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/cow.example.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:9899;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        # Replies stream over SSE: keep connections open and unbuffered
        proxy_read_timeout 3600s;
        proxy_buffering off;
        # File uploads up to 512 MB
        client_max_body_size 512m;
    }
}
```

**方法 2：HTTPS を直接有効化**。コンソール自身が TLS を提供します：

```json
{
  "web_https_enabled": true,
  "web_ssl_certfile": "/etc/letsencrypt/live/cow.example.com/fullchain.pem",
  "web_ssl_keyfile": "/etc/letsencrypt/live/cow.example.com/privkey.pem"
}
```

| パラメータ | 説明 | デフォルト |
| --- | --- | --- |
| `web_https_enabled` | コンソールを HTTPS で直接提供する | `false` |
| `web_ssl_certfile` | PEM 証明書ファイル（フルチェーン推奨） | `""` |
| `web_ssl_keyfile` | PEM 秘密鍵ファイル | `""` |

証明書ファイルが存在しない、または読み取れない場合は起動時にエラーで停止し、HTTP にはフォールバックしません。

<Note>
  コンソールはルートパスで公開する必要があります。`/cow/` のようなサブパスではなく専用のサブドメインを使ってください。OAuth が必要な MCP サーバーを使う場合は、`"mcp_oauth_redirect_base": "https://cow.example.com"` も設定してください。
</Note>

## チャット API

Web コンソールのポートでは OpenAI 互換のチャット API `/v1/chat/completions` も提供しています。初期状態では無効で、設定ページの「チャット API」カードから有効にして API キーを取得できます。詳しくは [チャット API](/ja/extensions/chat-api) を参照してください。

## 機能紹介

### チャット画面

ストリーミング出力に対応しており、Agent の思考プロセス（Reasoning）とツール呼び出しプロセス（Tool Calls）をリアルタイムで表示でき、Agent の意思決定をより直感的に観察できます。深い思考機能は設定またはコンソールの「Agent 設定」スイッチで制御できます。

<img width="850" src="https://cdn.link-ai.tech/doc/20260227180120.png" />

#### マルチセッション管理

チャット画面はマルチセッション（Session）管理に対応しています。すべてのセッション記録はデータベースに永続化されます：

- **セッション一覧**：左側の履歴セッションアイコンをクリックするとセッション一覧パネルを展開/折りたたみでき、スクロールですべての履歴セッションを読み込めます
- **AI によるタイトル生成**：新しいセッションの初回対話完了後、自動的にモデルを呼び出して短いセッション要約タイトルを生成します
- **新規セッション**：セッション一覧上部の「新しい会話」ボタンまたは入力エリアの `+` ボタンをクリックして新しいセッションを作成します
- **セッション削除**：セッション項目の削除ボタンをクリックし、確認後にそのセッションとすべてのメッセージを完全に削除します
- **コンテキストクリア**：入力エリアのクリアボタンをクリックすると、現在のセッションに区切り線が挿入されます。区切り線より上のメッセージは表示されたままですが、モデルのコンテキスト入力には含まれなくなります
- **ワークスペース / モデル / 権限**：入力欄の下で、現在のセッションにワークスペース・モデル・権限モードを個別に設定できます。複数のプロジェクトを使う場合、過去のセッションは自動的にプロジェクトごとにグループ化されます。詳しくは [アーキテクチャ - プロジェクトワークスペース](/ja/intro/architecture#project-workspace) を参照してください

#### 権限モード

セッションごとに権限モードを設定し、Agent がファイルやコマンドに触れる範囲を制御できます：読み取り専用（read-only）、ワークスペース書き込み可（workspace-write）、フルアクセス（full-access）。権限でツール呼び出しがブロックされた際は、その場で調整できるクリック可能なヒントが表示されます。
