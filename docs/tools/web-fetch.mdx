---
title: web_fetch - Web Fetch
description: "The web_fetch tool retrieves HTTP and HTTPS URLs, extracting readable text from web pages and downloading and parsing PDF, Word and Excel files. Use the browser tool for JavaScript-rendered pages."
---

Fetch the content of an HTTP/HTTPS URL. Web pages are extracted as readable text; document files (PDF, Word, Excel, etc.) are downloaded and parsed automatically.

## Parameters

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `url` | string | Yes | HTTP/HTTPS URL (web page or document) |

## Supported file types

| Type | Formats |
| --- | --- |
| PDF | `.pdf` |
| Word | `.docx` |
| Text | `.txt`, `.md`, `.csv`, `.log` |
| Spreadsheet | `.xls`, `.xlsx` |
| Presentation | `.ppt`, `.pptx` |

## Use cases

- Extract readable text from a web page
- Download and parse remote documents
- Inspect API response bodies

## DeepSeek Fetch backend (opt-in)

By default `web_fetch` retrieves pages directly. Set `tools.web_fetch.provider`
to `"deepseek"` to fetch through [DeepSeek's official Fetch API](https://api-docs.deepseek.com/guides/search)
instead, which returns the page as Markdown — handy for pages the direct
backend cannot render (e.g. JavaScript-heavy sites).

```json
{
  "tools": {
    "web_fetch": {
      "provider": "deepseek"
    }
  }
}
```

The backend uses the `deepseek_api_key` model credential (or the
`DEEPSEEK_API_KEY` environment variable). Calls are billed per
successful request ($0.75 per 1,000), so the backend stays opt-in; `"direct"`
(the default) is free. The SSRF guard still applies: private, loopback, and
cloud-metadata URLs are rejected before any request is issued. Document
URLs (PDF, Word, etc.) are always downloaded and parsed locally.

## Olostep backend (opt-in)

Set `tools.web_fetch.provider` to `"olostep"` to fetch through
[Olostep's Scrape API](https://docs.olostep.com/features/scrapes) instead.
Olostep renders the page in a browser and returns it as Markdown, so it also
works on JavaScript-heavy sites.

```json
{
  "tools": {
    "web_fetch": {
      "provider": "olostep"
    }
  }
}
```

The backend uses the same key as the Olostep search provider,
`tools.web_search.olostep_api_key` (or the `OLOSTEP_API_KEY` environment
variable); create one in the [Olostep dashboard](https://www.olostep.com/dashboard/api-keys).
Each scrape uses Olostep credits, so the backend stays opt-in. The SSRF guard
still applies, and document URLs (PDF, Word, etc.) are still downloaded and
parsed locally.

## WebRouter backend (opt-in)

Set `tools.web_fetch.provider` to `"webrouter"` to fetch through
[WebRouter](https://docs.webrouter.net), an open-source Python library that
tries several extract APIs in turn and returns the page as Markdown. It needs
no key: with none it uses keyless extract backends.

```json
{
  "tools": {
    "web_fetch": {
      "provider": "webrouter"
    }
  }
}
```

The backend needs the `webrouter` package (`pip install webrouter`, Python
3.11+). WebRouter also reads provider keys from the process environment (such
as `TAVILY_API_KEY` or `FIRECRAWL_API_KEY`) and adds those providers to its
routing, so fetches it sends to them are billed to those keys. The page is
fetched by those hosted APIs, not from this machine. The SSRF guard still
applies to the URL, and document URLs (PDF, Word, etc.) are still downloaded
and parsed locally.

<Note>
  The default `direct` backend only retrieves static HTML. For pages that require JavaScript rendering (such as SPAs), switch to the DeepSeek or Olostep backend above, or use the `browser` tool.
</Note>
