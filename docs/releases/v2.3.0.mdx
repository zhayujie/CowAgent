## 📱 Mobile App

CowAgent now has a mobile app for iOS, Android, and HarmonyOS, on both phones and tablets. The app works in two ways: run the Agent directly on your phone, or connect to CowAgent on a computer or server.

> The app is in public beta. On iOS, install it through TestFlight; on Android, download the APK directly; on HarmonyOS, install it through the invitation test in Huawei AppGallery. The official release is coming to app stores soon. Scan the code on the [download page](https://cowagent.ai/download/#mobile) to install. Give it a try, and share issues or suggestions through [GitHub Issues](https://github.com/zhayujie/CowAgent/issues).

- **Run on your phone**: the app includes the full Agent core, so no computer or server is needed. Once a model is configured, chat, skills, memory, the knowledge base, and scheduled tasks are all available, with data stored locally on the phone.
- **Connect to other devices**: scan a pairing QR code to connect to CowAgent on a computer or server, then continue conversations, view artifacts, and manage tasks from your phone. Multiple devices can be saved and switched at any time.
- **Phone capabilities**: when running on the phone, the Agent can open apps and links (navigation, calls, texts, email), get your location, read and write the calendar, look up contacts, pick photos, share files, and check device status. It asks before each action, and you can choose to always allow it.
- **Notifications and reminders**: while the app is in the background, completed replies and scheduled task results arrive as system notifications, and tapping one opens the conversation. Scheduled tasks created on the phone are run on time by the system.
- **Chat experience**: supports streaming replies, attachments, and voice input, and multiple sessions can reply at the same time. Replies can be stopped at any time, interrupted replies can be continued, and you can regenerate a reply or edit a sent question.
- **Files**: files and text from other apps can be shared straight into a conversation, and files in a conversation can be shared to other apps.
- **Full management**: Agents, skills, MCP, the knowledge base, memory, scheduled tasks, channels, guest pages, models, and capabilities are configured the same way as in the Web console, and can all be managed on the phone.
- **Other**: multilingual interface; device credentials are stored in the iOS Keychain and Android Keystore.

## 🔗 Device Management

The Web console, desktop client, and mobile app now have device management. They can connect to each other, so CowAgent on multiple devices can be operated from one place:

- **Pairing**: on the Devices page, click "Let a device connect" to generate a QR code and pairing code (valid for 5 minutes and usable once). Phones connect by scanning the code; computers connect by entering the address and pairing code. On a server without a graphical interface, run `cow pair` to show the pairing code and QR code in the terminal.
- **Device switching**: the Web console, mobile app, and desktop client can connect to CowAgent instances on other computers or servers and switch between devices, for example to manage the Agent on a server from your phone or laptop.
- **Cloud instances**: instances on [CowAgent Cloud](https://docs.cowagent.ai/guide/cloud) also support pairing. After scanning the code, your phone can use the instance from any network, wherever you are.
- **Device list**: "Devices connected to me" lists every connected device with its connection method (paired or password sign-in) and last active time. Devices can be renamed or removed, and a removed device is disconnected immediately.
- **Separate credentials**: each device has its own sign-in credentials, which the Agent cannot read.

## 🤖 Model Capabilities

- **CowAgent model service**: a single API key gives access to mainstream models such as Claude, GPT, Gemini, DeepSeek, and Qwen, and also covers image understanding, image generation, speech, embeddings, and web search. Related docs: [CowAgent Model Service](https://docs.cowagent.ai/models/cowagent)

## 🛡 Security Hardening

- **Sign-in credentials**: credentials are decoupled from the password, so a leaked credential cannot be used to recover the password; only client IPs passed by a reverse proxy on the same machine are trusted, and keys and passwords in logs are masked automatically.
- **Vulnerability fixes**: fixed an XSS in the MCP authorization callback page, the image understanding tool respects credential path protection, validation of plugin installs, skill names, and admin passwords is stricter, and a gap in command permission checks is fixed (Thanks @MrGendo #3948, #3949, #3950, #3951, #3958, #3959, #3961); the Feishu long connection verifies TLS certificates (Thanks @failsafesecurity #3796); SSRF protection covers the carrier-grade NAT range and Feishu image links (Thanks @rudycelekli #3913, @c020627 #3916); script-type files are opened in a sandbox in the console (Thanks @zkjqd #3938).

## 📦 How to Upgrade

- **Source deployment**: run `cow update` for a one-click upgrade, update from the version menu in the Web console sidebar, or pull the latest code and restart. See the [upgrade guide](https://docs.cowagent.ai/guide/upgrade).
- **Desktop client**: check for updates and update with one click inside the client, or get the latest version from the [download page](https://cowagent.ai/download/).
- **Mobile app**: in public beta. Install through TestFlight on iOS, download the installer on Android, or join the invitation test in Huawei AppGallery on HarmonyOS. See the [download page](https://cowagent.ai/download/#mobile) and the [mobile docs](https://docs.cowagent.ai/guide/mobile#download-and-install).

Before upgrading, note:

- To connect from the mobile app or another device, the CowAgent being connected to must be 2.3.0 or later, and its listen address must be reachable (not local-only). Setting an access password is recommended.
- If pages on another website need to call the console API, add that site to `web_allowed_origins`.
- When accessing through a reverse proxy such as Nginx, forward the `Host` and `X-Real-IP` headers so the access address and client IP are identified correctly.
