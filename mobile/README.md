# CowAgent Mobile

Mobile client for CowAgent. One React Native 0.82 codebase, plus RNOH (React Native for OpenHarmony), covers iOS, Android and HarmonyOS NEXT.

## Requirements

| Platform | Needs |
| --- | --- |
| All | Node ≥ 20.19.4 (`nvm install 22` / `nvm use 22` recommended) |
| Android | JDK 17, Android SDK (compileSdk 36, minSdk 24), NDK 27.1 |
| iOS | macOS with Xcode 16+, CocoaPods |
| HarmonyOS | DevEco Studio 6.x (target SDK 6.0.0(20), compatible with 5.0.0(12)), a device or emulator |

## Quick start

```bash
cd mobile
npm install

npm start            # Metro
npm run android      # Android
npm run ios          # iOS (first run: cd ios && bundle install && bundle exec pod install)
npm run web          # Browser preview on http://localhost:8090
```

### Browser preview

`npm run web` serves the app through react-native-web in a phone-sized frame and proxies API calls to
`http://127.0.0.1:9899`; set `COW_BACKEND` to point at another server. It is meant for UI work only:
platform modules such as the recorder, file picker and media player use `.web.ts(x)` browser implementations.

### Android release signing

Release builds are signed with the keystore described by the `COW_RELEASE_STORE_FILE`,
`COW_RELEASE_STORE_PASSWORD`, `COW_RELEASE_KEY_ALIAS` and `COW_RELEASE_KEY_PASSWORD` Gradle properties.
Put them in `gradle.properties` under your Gradle user home (or export them as environment variables), never in
this repo. Without them the release build falls back to the public debug keystore and is for testing only.

### HarmonyOS

1. Open `mobile/harmony` in DevEco Studio and wait for the ohpm sync.
2. Copy `harmony/build-profile.template.json5` to `harmony/build-profile.json5` and enable automatic signing under
   File > Project Structure > Signing Configs. That file holds certificate details and is git-ignored.
3. Build the JS bundle with `npm run bundle:harmony:release`. It writes
   `entry/src/main/resources/rawfile/hermes_bundle.hbc`, which is not committed.
   Release builds load only this file, so rebuild it after every JS change; without it the app shows a blank screen.
4. Debugging: debug builds connect to Metro first. Run `npm start`, then `hdc rport tcp:8081 tcp:8081`, then run
   `entry` from DevEco. If Metro is unreachable the app falls back to the bundle above.

Native ports are redirected by Metro through `harmony.alias` in `package.json`, so app code always imports the upstream
package names. The C++/ArkTS side is autolinked and code-generated by the rnoh hvigor plugin (`harmony/entry/hvigorfile.ts`).
gesture-handler, reanimated, worklets, screens and svg do not support autolinking and are registered by hand in
`entry/src/main/ets/PackageProvider.ets`, `entry/src/main/cpp/PackageProvider.cpp` and
`entry/src/main/cpp/CMakeLists.txt`; a new package of this kind needs all three.

## Layout

```
src/
  config/      Default server URL, timeouts and other constants
  protocol/    Message types shared with the server (SSE events, WS envelope)
  api/         HTTP client, CowAgent API, SSE reader
  realtime/    Shared WebSocket client (hello/ack/reconnect/dedup) and chat stream subscriptions
  storage/     Local key-value and credential storage
  store/       zustand stores: server/login, agents, sessions, chat, config, channels, MCP, menu
  screens/     Chat, agents, sessions, skills, MCP, knowledge, memory, tasks, channels, settings
  components/  Shared UI: sheets, forms, markdown, message bubbles, composer, file viewers
  navigation/  Routes, transitions and gestures
  media/ files/ Media picking/recording and chat file handling
web/           Browser preview (Vite)
harmony/       HarmonyOS project (RNOH)
android/ ios/  Native projects
```

## Connecting to the server

- The default server URL on the login screen comes from `src/config/defaults.ts` and is empty, so users enter
  their own address. The server must set `web_password`; otherwise the client refuses to connect.
- The server does not implement `/api/info` or the shared WebSocket `/ws` yet. On a 404 the client falls back to
  `/api/health` + `/auth/check`, and the chat stream uses the existing SSE `/stream` (resumable with `after_seq`).
  Once the server ships `/ws`, the client switches automatically when `/api/info` returns a `ws_url`, with no app changes.

## Known limitations / TODO

- `storage/secureStore.ts` is an AsyncStorage development implementation. Before release it must be backed by
  Keychain, Keystore and the HarmonyOS Asset Store Kit.
- Not integrated yet: FlashList, MMKV, network status, push notifications.
